# writing_style_guide.md

## 参考报告风格

对齐本 Skill 的通用报告模板和基准输出规范；它们只约束结构、证据密度与排版，不提供新报告的事实：

- 使用“判断 + 数据 + 解释 + 管理启示”的段落结构。
- 执行摘要用项目符号呈现 5 条核心判断。
- 趋势部分必须把数据变化和版本节点写在一起。
- 不回避负面原因，如广告、权益、BUG、期待升级。
- 对用户满意点单独成章，避免报告只有负面。
- 路线图按“即时/本季度/中期/长期”展开。
- 量化目标要写当前值与目标值。
- 七段式是最小骨架；当高危主题、异常峰值、设备分化或外部数据背离会改变决策时，增加深层归因章节。
- 完整月报要达到“一个核心命题 + 多层证据链 + 自适应深挖图表 + 可执行路线图”的密度，不按固定图数机械拼装。

## 推荐句式

- “这不是质量危机，而是……”
- “这是本报告最重要的归因证据。”
- “用户的差评本质是需求未被响应的信号。”
- “该问题声量不是最高，但均分最低，属于满意度毒药。”
- “不同设备本质上代表不同人群，不能用平均用户做排期。”
- “管理启示：……”
- “策略含义：……”

## 避免句式

- “体验有待优化。”
- “建议持续改进。”
- “用户反馈较多。”
- “详见下文。”
- “可能存在一些问题。”

以上句式过于空泛，必须替换为具体问题、具体人群、具体动作。
