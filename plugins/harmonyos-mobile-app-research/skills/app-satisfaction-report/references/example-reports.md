本 Skill 用两份互补报告定义输出标准：一份回答“应该怎样做”，一份回答“高质量成品应该是什么效果”。

规范示范中所说的“3 个 Skill”专指评论标签化、满意度分析和满意度报告这条子链路，不代表完整插件只有 3 个 Skill。

## 阅读顺序

生成完整月报、双周报或 DOCX 时，按以下顺序执行：

1. 读取 [基准报告输出规范](reference-output-spec.md)，确定不可缺少的结构和证据门禁。
2. 读取规范示范的 Markdown 伴读版，理解从数据到分析再到报告的完整流程。
3. 打开规范示范 DOCX，观察封面、章节层级、表格、分页和图文关系。
4. 读取实例示范的 Markdown 伴读版，理解一个核心命题如何贯穿全篇。
5. 打开实例示范 DOCX，校准成品的数据密度、图表节奏、重点突出方式和行动化程度。
6. 使用本期输入重新建立证据矩阵和核心命题，再开始写作。

只生成短摘要时，至少读取本文件、基准报告输出规范和实例示范的执行摘要；不得为了省略阅读而降低事实与数字核对标准。

## 分别学习什么

### 从规范示范学习

- 输入文件必须具备哪些字段；
- 标签化、趋势分析、主题分析和设备分析如何衔接；
- 每类图表需要什么数据、计算口径和解读；
- 七段式报告每一段必须回答什么问题；
- DOCX、Markdown 与跨平台交付应满足什么要求。

### 从实例示范学习

- 先提出一个有证据的核心命题，再用所有章节共同证明；
- 执行摘要直接给出可决策判断，每个判断紧跟数字或事实；
- 把版本节点、评论趋势、主题变化和设备差异放在同一证据链中；
- 当常规七段式不足以解释异常时，增加深层归因，而不是机械控制篇幅；
- 最终落到需求优先级、满意资产、分阶段路线图和量化目标。

## 可以模仿与禁止照搬

可以模仿：

- 信息层级、章节节奏、图表与文字的配合；
- “判断 → 证据 → 解释 → 行动启示”的写法；
- 样本量、时间窗、替代解释和限制条件的披露方式；
- 重点结论在 DOCX 中的视觉强调方式。

禁止照搬：

- 示例中的应用名称、版本、日期、样本量、评分和比例；
- 示例中的用户原话、设备结论、主题结论和优先级；
- 示例对商业化、会员、客服或具体功能的判断；
- 示例中的组织名称、编制日期和报告周期。

示范报告不是本期事实来源。用户范围、本期分析产物和可追溯证据始终优先；输入证据不足时，降级为待核验判断，不用示范内容补空缺。

## 快速定位

伴读版篇幅较长，可先搜索以下锚点，再按任务需要展开上下文：

```powershell
rg -n "输入规格|分析一|走势分析|设备 × 舆情|七段式|写作纪律" references/examples/report-method-standard.md
rg -n "执行摘要|版本迭代|深层归因|用户最迫切|用户满意|分阶段|量化目标" references/examples/kugou-harmony-satisfaction-gold-example.md
```

Markdown 伴读版用于检索正文和表格；最终排版、图表效果、分页和视觉密度必须以 DOCX 为准。如果当前环境无法渲染 DOCX，在交付说明中明确标记“内容已对齐，视觉效果未完成参考文档复核”。
